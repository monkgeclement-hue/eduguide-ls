## Core Data Files

### programmes.flat.json (★ Main Catalog)
**The central source of truth for all programmes in Lesotho**

Structure per programme:
```json
{
  "id": "institution-programme-name",
  "institution": "Institution Name",
  "name": "Programme Name",
  "category": "Field Category",
  "faculty": "Faculty Name (optional)",
  "level": "Degree|Diploma|Certificate",
  "duration": "X years with [project/attachment/...]",
  "requirements_summary": "Entry requirements",
  "source_url": "Where it came from",
  "source_type": "official_course_portal|official_js_bundle|...",
  "extraction_method": "How it was scraped",
  "review_status": "approved|needs_admin_review|duplicate|",
  "career_options": [
    "Career Path 1",
    "Career Path 2",
    "Career Path 3",
    "Career Path 4"
  ],
  "source_note": "Auto-enriched from repository evidence...",
  "supporting_fee_source_path": "data/real/fees/filename.json (optional)",
  "fee_note": "Fee schedule available... (optional)"
}
```

**Key Fields:**
- `id`: Unique identifier (kebab-case)
- `level`: Determines duration rules applied
- `career_options`: Generated by automation (see below)
- `review_status`: "approved" = ready for display
- `supporting_fee_source_path`: Links to fee data

### programmes.by-institution.json
Same data, organized hierarchically by institution for faster queries.

### Fee Structure Files
Located in `real/fees/`, each institution has:
```json
{
  "academic_year": "2024/25",
  "source_title": "NUL Fee Structure 2024/25",
  "institution": "National University of Lesotho",
  "fee_items": [
    {
      "programme_group": "Science",
      "level": "Degree",
      "tuition": 50000,
      "registration": 5000,
      "currency": "LSL"
    }
  ]
}
```

## Data Enrichment Automation

### What Gets Enriched?

1. **Career Paths** — Auto-matched from programme names using intelligent patterns
   - Stored in: `career_options` array (4 items max)
   - Example: "Software Engineering" → Software Developer, Systems Analyst, etc.

2. **Duration Rules** — Institution-specific programme length standards
   - Applied based on level (degree/diploma) and institution
   - Example: Limkokwing degrees = "4 years with project"

3. **Fee References** — Links to fee structure documents
   - Stored in: `supporting_fee_source_path` and `fee_note`
   - Helps users know where to find pricing

4. **Botho Filtering** — Remove non-Lesotho offerings
   - Keeps: programmes that mention "Lesotho"
   - Removes: programmes for Botswana/other regions only

### Running the Enrichment

```bash
# Automatic enrichment
python automate-data-population.py

# Result: programmes.flat.json is updated in-place
# A summary is printed showing changes made
```

**Output Example:**
```
✅ Enrichment complete!
  - Programmes processed: 234
  - Botho programmes filtered: 1
  - Career paths enriched: 45
  - Final programme count: 233
```

## Using the Data

### In the Application

**Supabase Integration:**
```sql
-- Load from seed during migration
SELECT * FROM programmes 
WHERE level = 'Degree' 
AND career_options @> '["Software Developer"]'
ORDER BY institution;
```

**API Endpoint (backend):**
```javascript
// server.py
GET /api/programmes?institution=nul&level=degree
GET /api/programmes?category=Technology
GET /api/programmes/search?q=engineering
```

### In the Frontend

**Browse by Career:**
```javascript
// app.js
const programmes = programmeData.filter(p => 
  p.career_options.includes("Software Developer")
);
```

**Browse by Institution:**
```javascript
programmesByInstitution["National University of Lesotho"]
  .filter(p => p.level === "Degree")
```

**Filter by Duration:**
```javascript
programmes.filter(p => p.duration.includes("4 years"))
```

## Data Governance

### Adding New Programmes

1. **Manual Addition**: Edit `programmes.flat.json` with complete data
2. **Automation Enrichment**: Run `automate-data-population.py` to fill missing fields
3. **Validation**: Check `review_status` is set to "approved"
4. **Git Tracking**: Commit with source reference in `source_note`

### Updating Existing Data

1. **Fee Updates**: Update corresponding fee file in `real/fees/`
2. **Programme Changes**: Edit in `programmes.flat.json`
3. **Re-Enrichment**: Run automation if duration/career paths need refresh
4. **Validation**: Check changes in `git diff` before committing

### Handling Data Conflicts

If you see conflicting data:
1. Check `source_audit.json` for source reliability
2. Verify against `source-coverage.json` for completeness
3. Review in `programmes.by-institution.json` for institution-specific version
4. Mark as `needs_admin_review` if uncertain

## Maintenance

### Regular Tasks

- **Weekly**: Check for new fee updates from institutions
- **Monthly**: Run enrichment automation to catch new programmes
- **Quarterly**: Audit sources in `source-audit.json`
- **Annually**: Archive old fee structures, update current year

### Troubleshooting

**Missing career options?**
- Check pattern in `data-enrichment.conf`
- Add regex pattern if new field type

**Wrong duration applied?**
- Verify institution name matches exactly
- Check level (degree vs diploma) is correct

**Programmes not showing?**
- Check `review_status` is "approved"
- Verify source_url is not null
- Check institution name is in the whitelist
